# 2026-10-29 구현 보완

검색과 생성 사이에서 근거가 사라지는 문제를 먼저 수정했다. 데이터 추출과 문서 구역 처리, 검색 모드 표시를 함께 점검하고 공개 가상 자료와 합성 사례로 동작을 확인했다.

| 문제 | 변경 | 확인한 범위 |
|---|---|---|
| 긴 구역의 뒤를 검색해도 앞 2,200자만 생성에 전달됨 | 선택 청크 전체를 포함하는 최대 2,200자 주변 문맥 사용 | 2,200자 이후의 근거가 생성 입력과 출처 발췌에 남는지 검사 |
| 같은 부모 문맥의 서로 다른 검색 청크가 중복으로 제거됨 | 과목·구역·선택 본문이 같은 경우에만 중복 제거 | 앞·뒤 근거를 함께 유지하고 동일 근거만 제거하는지 검사 |
| BM25 재작성 검색이 `chroma_gemini`로 표시됨 | 실제 검색 경로에 따라 `keyword_rewrite`와 `hybrid_rewrite` 구분 | 가짜 SDK로 검색 경로와 최종 모드 확인; 모델 호출 없음 |
| 같은 데이터·청크 수의 오래된 인덱스가 재사용될 수 있음 | `chunking_version` 검사와 기존 청크 메타데이터 갱신 | 이전 버전 배제, 본문이 같을 때 임베딩 호출 없이 문맥 갱신 |
| 알려진 구역 제목 변형이 일반 본문에 섞임 | 강의개요·수업목표·주차별 강의계획을 기존 구역에 연결 | 주차 표 안의 교재·시험 표현은 구역을 나누지 않는지 검사 |
| HTML의 빈 평가 안내가 첨부의 평가 내용과 함께 검색됨 | 빈 안내 제거, 여러 자료의 평가 내용은 출처별 표시 | 평가 값이 다른 첨부·HTML을 한 값으로 확정하지 않는지 검사 |
| 체크박스의 모든 선택지가 활동 근거가 될 수 있음 | 명시적으로 선택된 항목만 추출 | label 연결·인접 텍스트·선택된 option 검사; 연결 불명확한 표 행은 생략 |

토큰화와 동의어 규칙은 `sugang_mate/query_text.py`, 생성 문맥은 `context.py`, 추출문 정리는 `source_text.py`, HTML 양식 처리는 `html_text.py`로 분리했다. 대화와 질문 분기 구조는 유지했다.

## 실행한 검사

Python 3.12와 Gradio 6.17.3에서 외부 모델을 끄고 실행했다.

```bash
python -m unittest discover -s tests -v
python scripts/record_validation.py
```

자동 테스트 139개와 공개 실행 시나리오 5개가 통과했다. 공개 파일의 Python 문법·문서 링크·비밀 파일 제외와 Gradio 화면 구성도 확인했다. 결과와 코드 해시는 [현재 검사 기록](../evaluation/release-checks.json)에 남겼다. [2026-09-10의 126개 검사 기록](../evaluation/release-checks-2026-09-10.json)은 별도로 보존했다.

## 이번에 확인하지 않은 범위

실제 25개 과목의 원문과 정제본을 작업 환경에서 확보하지 못했다. 운영 데이터를 수정하지 않았고 원문 재추출, 기존 103문항 회귀, 30문항 검색 진단, Gemini 호출을 다시 실행하지 않았다. 이번 자동 검사 결과는 실제 서비스의 답변 정확도나 개선율을 뜻하지 않는다.

구역 제목과 빈 평가 안내 처리는 기존 JSONL을 읽을 때도 적용된다. HTML 선택 상태 개선은 원본 HTML을 다시 추출해야 적용된다. 이미 문자나 선택 상태가 사라진 텍스트에서 원래 값을 추정하지 않는다. 독립적인 실제 서비스 답변 품질 평가와 사용자 연구는 이번 작업에 포함하지 않았다.

배포 여부와 공개 서버 확인은 로컬 검사와 별개다. 이 문서의 오프라인 결과만으로 운영 서버가 변경되었다고 판단하지 않는다.
