# 주요 설계 결정

## 질문에 따라 구조화 조회와 검색을 선택

시간표·개수·전체 목록은 검색 top-k에 따라 일부 과목을 누락하면 안 된다. 해당 질문은 과목 메타데이터와 분반 정보를 직접 조회한다. 내용 질문에는 문서 검색과 근거 추출 또는 생성 답변을 사용한다. 두 경로의 지표·지연시간·오류 원인을 분리해 보고한다.

## 공개 예시와 실제 데이터 분리

GitHub에는 직접 작성한 가상 과목 6개를 제공하며, `run_demo.py`는 이 예시를 오프라인으로 실행한다. 공개 웹 서비스는 프로젝트에서 수집한 실제 25개 과목의 정제본을 Render Secret File로 읽는다. 연락처와 로컬 경로를 제거한 파일의 해시·문서 수가 검토 기록과 일치해야 시작하며, 파일이 없을 때 예시 데이터로 바뀌지 않는다. 따라서 방문자에게 원문 파일·API 키·학교 로그인을 요구하지 않는다. 원본 자료와 벡터 DB는 공개 저장소에 포함하지 않는다.

## 설정과 캐시 모듈 분리

기존 답변 로직은 회귀 결과를 유지하면서 설정·데이터 경로·캐시를 `sugang_mate/`로 옮겼다. 기존 PC의 설치 폴더에 의존하는 경로 조작을 제거했다. 부모 폴더의 `.env`를 읽지 않고 호출 환경의 설정이 로컬 `.env`보다 우선하도록 했다.

TTL/LRU 캐시는 읽을 때 TTL을 연장하지 않고, 입력·반환 객체를 각각 복사한다. 최대 크기 또는 TTL이 0이면 비활성화한다. 일시적 모델 장애 응답은 저장하지 않는다. 대화 맥락은 먼저 해석한 후 캐시를 적용하며 서로 다른 과목을 가리키는 같은 후속 질문을 검사한다.

## 데이터와 다른 벡터 DB 배제

청크 수가 같아도 데이터 내용은 다를 수 있다. 인덱스 수·데이터 SHA-256·임베딩 모델을 확인한다. 정보가 없거나 일치하지 않으면 로컬 검색으로 실행한다. 인덱스 생성 중에는 유효 표시를 제거하고, 완료 후에만 데이터 해시를 기록한다. 옛 인덱스는 새 스크립트로 다시 생성해야 한다.

## 화면의 근거와 상태

과거 출처 화면은 최대 5개 과목만 표시했다. 전체 목록 응답에 포함된 출처를 숨기지 않도록 제한을 제거하고 검사했다. 화면 상단은 실제로 읽은 데이터의 종류와 과목 수를 표시한다. 질문 길이는 UI와 직접 함수 호출 모두에서 제한하고, 처리 실패 시 이전 근거나 내부 예외 내용을 답변으로 표시하지 않는다.

피드백 파일과 브라우저 대화 영구 저장은 공개 예시에서 기본 비활성화했다. 모델 변경은 지정한 모델만 기본 사용하며 자동 대체 모델은 `GEMINI_FALLBACK_MODELS`에 명시했을 때 사용한다.

## 후속 질문의 부분집합 처리 수정

실제 화면 검증에서 두 과목을 비교한 뒤 “그중 전공필수는?”이라고 물으면 전공선택 과목까지 기본정보를 반환하는 문제가 드러났다. 이수구분의 부분집합·개수 질문을 일반 메타데이터·개수 처리보다 먼저 판단하도록 수정했다. 다른 전공필수 과목이 전체 데이터에 있어도 직전 과목 집합을 벗어나지 않는지, 결과가 0개인 경우도 테스트했다. 이 과정에서 사용한 질문은 회귀 테스트이며 신규 검색 진단 세트와 별개다.

수정 후 실제 브라우저에서도 DEMO201·DEMO202를 비교한 뒤 전공필수를 묻는 질문에 DEMO201만 반환하는 것을 확인했다. [후속 질문 화면](assets/demo-followup.png)

## 활동 조건을 적용한 뒤 개수 계산

최종 공개 검토에서는 개인 프로젝트가 있는 과목이 프로젝트 필터에서 빠지고, “그중 프로젝트가 있는 과목은 몇 개야?”가 필터 적용 전 개수를 반환하는 문제도 확인했다. 개인·개별 프로젝트를 근거로 인식하되 팀 활동과 구분하고, 기존 조건 파서를 직전 과목 집합에 먼저 적용한 뒤 개수를 계산하도록 수정했다. 프로젝트·PBL·복합 조건·학점·요일 및 조건 없는 전체 개수에 대한 회귀 검사를 추가했다.

## 다음 리팩터링

`app.py`에는 질문 규칙과 기존 HTTP 화면 코드가 많이 남아 있다. 공개 실행은 Gradio로 통일했지만 전체 답변 엔진 재작성까지 진행하지 않았다. 신규 기능을 추가할 때는 질문 해석·구조화 조회·응답 생성을 차례로 분리하고 현재 회귀 검사를 유지한다. 임의 코퍼스로의 일반화, 한국어 토큰화, 구역 경계 품질은 추가 검증 대상이다.
