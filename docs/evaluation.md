# 평가 설계와 결과

작성일: 2026-09-10. 기능 회귀, 저장된 과거 기록 감사, 신규 검색 진단을 분리한다. 실제 모델 연결은 [API 검증 기록](live-api-validation.md)에서 별도로 다룬다. 어떤 결과도 독립적인 실제 사용자 정확도 또는 LLM 답변 전체 사실성의 100%를 뜻하지 않는다.

## 1. 현재 공개본 코드의 기능 회귀

실제 정제 데이터 25개 문서·307개 청크에 대해 기존 103개 질문의 명시적 검사 조건을 재실행했다. `SUGANG_OFFLINE=1`, `ANSWER_CACHE_MAX=0`으로 설정해 외부 모델과 답변 캐시를 사용하지 않았다. 103/103이 통과했다.

검사 범위는 기대 과목 출처, 응답 모드, 지정된 문자열 조건, 중복 출처, 범위 밖 질문, 동의어 일관성이다. 질문별로 지정되지 않은 조건은 검사하지 않는다. 기존 스크립트의 Recall@k·MRR·nDCG는 답변의 최종 과목 출처 기준이며 검색기의 청크 순위 지표로 소개하지 않는다. 단일 PC에서의 처리시간은 운영 서비스 지연시간과 다르다.

집계 결과와 코드·코퍼스 해시: [release-regression.json](../evaluation/release-regression.json). 실제 질문별 답변 파일은 로컬 `data/evaluation/release_regression/`에 보관하며 공개 패키지에서 제외한다.

## 2. 기존 300개·2,500개 기록 감사

과거 결과 파일을 다시 집계했다. 과거 모델 호출을 다시 실행한 결과가 아니다.

| 항목 | 기존 300개 | 개선 후 300개 |
|---|---:|---:|
| 정의된 조건 통과 | 273 | 300 |
| 통과율 | 91.0% | 100.0% |
| 모델명이 기록된 응답 | 94 | 6 |

질문 순서·기대 과목·채점 조건이 같은지 직접 비교했다. 이 결과는 구조화 조회를 포함한 기존 서비스 변경의 회귀 사례로 활용할 수 있으나, 실행 환경·모델·코드 등 모든 조건이 고정된 새 통제 실험으로 볼 수는 없다. 실제 API 호출 수나 비용 절감률도 도출하지 않는다.

2,500개 기록의 `chroma_gemini` 응답은 43개다. 답변 문자열 조건이 지정된 항목은 634개이고 1,866개는 비어 있다. 비어 있는 조건은 해당 문자열 검사만 자동 충족하며 다른 출처·모드 검사는 계속 적용된다. 따라서 “2,500개 LLM 답변의 사실성이 모두 검증됨”이라는 표현은 사용하지 않는다.

재집계 코드: [audit_legacy_evaluation.py](../scripts/audit_legacy_evaluation.py)  
원본 해시와 집계: [legacy-audit.json](../evaluation/legacy-audit.json)

## 3. 신규 검색 진단: 청킹 방법 비교

**질문 출처:** 저장된 원문을 확인한 에이전트 작성 질문 30개·15개 과목. 사람이 만든 블라인드 홀드아웃이 아니다. 질문마다 과목·구역·짧은 근거 문구를 사전에 지정했으며 생성 답변에서 정답을 만들지 않았다. 질문에 따라 다른 과목도 관련될 수 있으므로 라벨은 완전한 관련도 집합이 아니다. 결과를 본 뒤 검색 로직을 이 질문에 맞춰 튜닝하지 않았다.

**공통 조건:** 동일 코퍼스, 동일 기본 토큰화·BM25(k1=1.5, b=0.75), 청크 크기 최대 900자, 겹침 120자, 상위 5개 청크. 과목 코드·과목명을 두 방식 모두에 붙인다. 질문 확장·문서 구역 가중치·질문 라우팅·벡터·LLM·캐시는 제외한다. 비교 대상은 정확한 고정 길이 윈도와 기존 구역/문장 경계를 보존하는 분할 정책이며 순수한 구역 라벨 효과만 분리한 실험은 아니다.

| 지표 | 고정 길이 + BM25 | 구역별 분할 + BM25 |
|---|---:|---:|
| 청크 수 | 153 | 307 |
| 기대 과목 Recall@5 chunks | 60.0% (18/30) | 56.7% (17/30) |
| 근거 포함 과목 Recall@5 chunks | 50.0% (15/30) | 33.3% (10/30) |
| 상위 5개 청크 내 중복 제거 과목 MRR | 0.4733 | 0.4722 |

과목 Recall의 분모는 질문의 기대 과목 수다. 동일 과목 청크를 여러 번 검색해도 점수를 중복 계산하지 않는다. 근거 포함 과목 Recall은 기대 과목의 지정 문구가 상위 청크 본문에 실제 포함될 때만 적중으로 계산한다. 문구 하나가 발견되는 것이 답변에 필요한 모든 사실을 확보했다는 뜻은 아니다. 구역명은 입력 라벨 검증에 활용하며 별도의 독립 인간 구역 정확도 지표는 계산하지 않는다.

**해석:** 이 진단에서는 구역별 분할의 우월성이 확인되지 않았다. 청크의 길이·경계·수가 바뀌면 BM25의 길이 정규화와 상위 결과 구성이 함께 달라진다. 이는 가능한 원인이며 원인별 효과를 분리해서 검증한 결과는 아니다. 이 수치를 실제 앱의 하이브리드 검색 정확도로 해석하지 않는다.

### 대표 실패

| 질문 ID | 기대 과목 | 고정 길이 근거 적중 | 구역별 근거 적중 | 확인한 현상 |
|---|---|---|---|---|
| R01 | BDSC155 | 실패 | 실패 | 미적분 범위의 지정 근거를 상위 5개에 확보하지 못함 |
| R02 | BDSC155 | 실패 | 실패 | 참여도·발표 관련 근거를 확보하지 못함 |
| R03 | BDSC201 | 실패 | 실패 | 선수 권장 과목의 근거를 확보하지 못함 |
| R05 | BDSC203 | 성공 | 실패 | R/Python을 활용하는 방법론 질문에서 분할 방식별 결과가 달라짐 |
| R09 | BDSC212 | 실패 | 실패 | PINN 구현에 대한 지정 근거를 확보하지 못함 |

재현 명령:

~~~powershell

~~~

## 4. 구현 검증

오프라인에서 외부 클라이언트를 불러오지 않는지, 설정 우선순위, 캐시 TTL·LRU·복사 격리·동시 접근, 서로 다른 대화의 후속 질문, 오래된 인덱스 배제, 공개 예시 조회와 비교, 출처 전체 표시, 긴 입력 제한, 내부 오류 표시, 지표의 분모·중복·라벨 유효성을 자동 검사한다.

~~~powershell
python -m unittest discover -s tests -v
python scripts/verify_release.py
~~~

초기 공개 시점에는 Windows / Python 3.12의 새 가상환경에서 자동 테스트 32개와 공개 시나리오 5개를 확인했고 **Windows·Ubuntu × Python 3.11·3.12의 네 환경이 모두 통과**했다. [당시 실행 기록](https://github.com/JunH14/sugang-mate/actions/runs/34426806501)을 보존한다. 추가 수정 이후의 테스트 수·결과·코드 해시는 [release-checks.json](../evaluation/release-checks.json), 원격 실행 결과는 [최신 GitHub 검사](https://github.com/JunH14/sugang-mate/actions/workflows/checks.yml)를 기준으로 한다.

첫 원격 실행에서 발견한 Python 3.11의 f-string 문법 차이와 Windows 짧은 경로 표기 차이를 수정한 뒤 통과했다. CI는 외부 모델 API를 호출하지 않는다.

## 5. 실제 API와 공개 실행

실제 Gemini 연결의 요청 조건, 응답 상태, 근거 대조 결과는 [API 검증 기록](live-api-validation.md)에 정리한다. 이 확인은 오프라인 기능 회귀나 독립적인 생성 품질 평가와 구분한다. 공개 예시의 설치·배포·요청 제한 조건은 [배포 안내](deployment.md)에서 확인할 수 있다.

## 6. 추가 검증 과제

- 벡터 DB 재구축을 포함한 동일 조건의 생성 품질·장애 대응 비교
- 동일 조건의 벡터 단독·하이브리드 검색 비교
- 사람이 작성하고 개발 과정과 분리한 최종 평가 질문
- 실제 사용자 유용성·만족도·시간 절감
- 인터넷 배포의 부하·비용·운영 안정성

자동 테스트·대표 API 요청·공개 접속 확인과 위 항목의 검증 완료를 구분한다. 실제 사용성 검증은 [별도 절차](user-study.md)를 준비했다.
