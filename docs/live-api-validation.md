# 실제 API 연결 검증

실제 Google Gemini 호출을 계측해 연결 성공과 답변의 근거 품질을 따로 확인한다. API 키, 학교 원문, 전체 질문별 답변과 프롬프트는 공개하지 않는다.

## 현재 확인한 범위

가상 6과목에서 8개 흐름을 실행해 기술 조건은 8개 모두 충족했다. 이 중 생성 질문 6개는 Gemini가 실제 답변했고, 평가방식 비교와 후속 조건 조회 2개는 외부 호출 없이 처리했다. 최초 실행의 생성 호출은 6회 모두 성공했고 SDK 보고 사용량은 입력 2,320토큰·출력 451토큰이었다.

근거를 직접 대조하니 감성 분류 질문에서 학습목표가 누락되고, 두 과목 비교에서 공통 주차계획을 차이처럼 사용하는 한계가 발견됐다. **연결 성공을 답변 정확도로 계산하지 않는다.** 최초 결과와 코드 해시는 [기준 실행 기록](../evaluation/live-api-baseline.json)에 보존했다.

현재 검색된 과목의 개요·학습목표를 생성 근거에 보충하는 변경을 추가 검증 중이다. 실제 25과목의 임베딩은 307청크 중 224개까지 생성됐고, API 한도 응답 2회를 기록했다. 이 단계의 학교 자료 전체 검증은 아직 완료로 표시하지 않는다. 최종 실행 수치와 질문별 판정은 [API 검사 기록](../evaluation/live-api-checks.json)을 확인한다.

## 어떻게 확인하는가

- 생성·임베딩 SDK 호출 직전에 횟수를 세고 성공·실패·모델·처리 시간·응답 사용량을 기록한다.
- 캐시와 SDK 자동 재시도를 끄고, 앱 시도 횟수 1회·요청당 20초 제한을 적용한다.
- 가상 데이터는 BM25 + Gemini, 실제 자료는 새로 만든 Chroma + BM25 + MMR + Gemini 경로를 확인한다.
- 과목 조회·후속 질문은 구조화 응답으로, 문서에 없는 질문은 미확인 안내로 처리되는지 함께 검사한다.
- 정답 과목 집합과 처리 방식은 자동으로 검사하고, 답변 내용은 로컬 원문과 별도로 대조한다.

## 재실행

가상 자료만 전송하는 기본 검사:

```bash
python -m pip install -r requirements-rag.txt
python scripts/validate_live_api.py --run --key-env .env
```

보유한 학교 자료를 Google에 전송할 권한이 있는 경우에만 다음 옵션을 추가한다. 실제 자료 파일은 공개 저장소에 포함하지 않는다.

```bash
python scripts/validate_live_api.py --run --key-env .env --with-private-corpus
```

상세 답변과 프롬프트는 무시되는 `artifacts/`, 실제 인덱스는 `data/vector_db/live-validation/`에 저장된다. 공개 보고서에는 민감 정보 없는 과목 질문, 처리 결과, 수치와 코드·데이터 해시만 기록한다. 임베딩 사용량이 반환되지 않으면 0원으로 해석하지 않는다.

## 해석의 한계

개발 중 작성한 소수 진단 질문을 단일 환경에서 순차 실행한 결과다. 원문 대조는 AI 도구를 이용한 검토이며 독립 평가자의 블라인드 평가가 아니다. 운영 사용자 정확도, 부하 처리량, 월간 비용을 나타내지 않는다. 모델 출력 변동과 검증 도중의 근거 선택 변경을 고려해 기준 실행과 최종 실행을 구분한다.
