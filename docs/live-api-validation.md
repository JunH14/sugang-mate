# 실제 API 연결 검증

실제 Google Gemini 호출을 계측해 연결 성공과 답변의 근거 품질을 따로 확인한다. API 키, 학교 원문, 전체 질문별 답변과 프롬프트는 공개하지 않는다.

## 최종 확인 결과

2026-09-10, `gemini-3.1-flash-lite`와 `gemini-embedding-001`로 실제 요청을 보냈다. 가상 6과목과 실제 25과목에서 **16개 흐름의 기술 조건을 모두 충족**했다. 이 중 12개 질문은 실제 생성 요청으로 답했고, 4개는 구조화 조회·후속 조건 조회·범위 밖 안내로 처리했다. 실제 자료의 307청크 임베딩과 Chroma 인덱스 검증도 완료했다.

| 최종 실행 항목 | 관측 결과 |
|---|---:|
| 질문별 기술 조건 검사 | 16/16 충족 |
| 실제 생성 응답 | 12회 성공 |
| 임베딩 요청 | 문서 배치 6회 + 질의 6회 성공 |
| 최종 실행의 SDK 요청 | 24회 성공 · 실패 0회 |
| SDK 보고 생성 사용량 | 입력 9,177 · 출력 969 · 합계 10,146토큰 |
| 생성 질문의 전체 응답 시간 | 중앙값 2.896초 · 최대 3.948초 |
| 원문 대조 검토 | 15개 충족 · 1개 가독성 개선 필요 |

원문 대조에서 12개 생성 응답의 사실 주장은 근거가 확인됐다. 다만 실제 과목의 구조화 평가 비교(P07)는 HWP 추출 과정의 깨진 문자를 그대로 표시하는 한계가 남았다. **연결 성공이나 이번 소수 질문의 검토 결과를 서비스 전체 정확도로 계산하지 않는다.** 질문별 조건·판정·코드 해시는 [최종 API 검사 기록](../evaluation/live-api-checks.json)에 남겼다.

## 실제 검증에서 발견하고 수정한 점

최초 가상 실행은 기술 조건 8/8을 충족했지만, 원문 대조에서 다음 두 문제가 발견됐다. 기존 검색 상위 5개 근거를 보존하고, 과목이 1~2개로 좁혀졌을 때 그 과목의 개요·학습목표를 최대 4개 보충했다. 생성 문맥은 최대 9구역, 구역당 2,200자로 제한했다.

| 같은 질문 | 최초 실행 | 수정 후 실행 |
|---|---|---|
| 감성별 텍스트 분류와 관련된 수업 | 과목은 찾았지만 학습목표를 놓쳐 미확인으로 답함 | 감성 분석·텍스트 분류가 명시된 목표를 근거로 답함 |
| DEMO101과 DEMO302의 차이 | 공통 주차계획을 사용해 차이 설명이 부족함 | 표 데이터 정제와 문서 검색·분류의 차이를 비교함 |

[최초 실행 기록](../evaluation/live-api-baseline.json)도 함께 공개한다. 검색 청크나 정답 라벨을 이 두 질문에 맞춰 변경하지 않았으며, 생성에 전달하는 근거를 보충했다. 동일 질문을 사용한 개발 중 수정 전후 관측으로, 독립 평가나 개선율 추정은 아니다.

## 요청 한도와 비용 해석

초기 임베딩 과정에서 HTTP 429 응답 2회를 관측했다. 완료한 224개 청크의 문서 일치를 확인한 뒤 재사용하고, 남은 83개는 16개 배치·35초 간격으로 생성했다. 최종 실행에서는 추가 오류가 없었다.

최초·재개·최종 실행을 합쳐 **SDK 요청 39회 중 37회 성공, 2회 한도 응답**을 기록했다. 생성 18회와 임베딩 21회이며, 임베딩에는 문서 배치 15회(성공 13·실패 2)와 질의 6회가 포함된다. 전체 실행의 생성 토큰 사용량 합계는 12,917이다. 실패 요청을 지우거나 최종 성공 수치에 섞어 숨기지 않았다.

문서 임베딩의 과금 사용량은 응답에 없었다. 호출·토큰 계측은 결제 명세가 아니며, 미반환 값을 0원으로 해석하지 않는다.

## 어떻게 확인하는가

- 생성·임베딩 SDK 호출 직전에 횟수를 세고 성공·실패·모델·처리 시간·응답 사용량을 기록한다.
- 캐시와 SDK 자동 재시도를 끄고, 앱 시도 횟수 1회·요청당 20초 제한을 적용한다.
- 가상 데이터는 BM25 + Gemini, 실제 자료는 새로 만든 Chroma + BM25 + MMR + Gemini 경로를 확인한다.
- 과목 조회·후속 질문은 구조화 응답으로, 문서에 없는 질문은 미확인 안내로 처리되는지 함께 검사한다.
- 정답 과목 집합과 처리 방식은 자동으로 검사하고, 답변 내용은 로컬 원문과 별도로 대조한다.

기술 조건에는 실제 생성 성공 이벤트, 필요한 질의 임베딩 성공 이벤트, 기대 과목 집합, 응답 모드, 캐시 미사용을 포함한다. 응답 화면의 모델 이름만으로 API 성공을 판정하지 않는다.

## 재실행

가상 자료만 전송하는 기본 검사:

```bash
python -m pip install -r requirements-rag.txt
python scripts/validate_live_api.py --run --key-env .env
```

보유한 학교 자료를 Google에 전송할 권한이 있는 경우에만 다음 옵션을 추가한다. 실제 자료 파일은 공개 저장소에 포함하지 않는다.

```bash
python scripts/validate_live_api.py --run --key-env .env --with-private-corpus
```

상세 답변과 프롬프트는 무시되는 `artifacts/`, 실제 인덱스는 `data/vector_db/live-validation/`에 저장된다. 공개 보고서에는 민감 정보 없는 과목 질문, 처리 결과, 수치와 코드·데이터 해시만 기록한다. 임베딩 사용량이 반환되지 않으면 0원으로 해석하지 않는다.

## 해석의 한계

개발 중 작성한 소수 진단 질문을 Windows·Python 3.12 환경에서 순차 실행한 결과다. 원문 대조는 AI 도구를 이용한 검토이며 독립 평가자의 블라인드 평가가 아니다. 운영 사용자 정확도, 부하 처리량, 월간 비용을 나타내지 않는다. 모델 출력 변동과 검증 도중의 근거 선택 변경을 고려해 기준 실행과 최종 실행을 구분한다.

실제 학교 자료의 HWP 문자 깨짐, 일부 출처 미리보기에서 과목 코드·URL 같은 메타데이터가 먼저 선택되는 현상은 남아 있다. 공개 배포는 직접 작성한 가상 과목만 사용하며, 실제 학교 자료·인덱스는 로컬 검증 범위에 둔다.
