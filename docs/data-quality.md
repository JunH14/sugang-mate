# 데이터 품질 보고서

이 보고서는 저장된 2026학년도 1학기(`2026-1R`) 자료를 다시 집계한 결과다. 현재 대학 개설 과목 전체를 대조하거나 웹에서 재수집한 결과가 아니다. 연락처와 원문 전체는 이 보고서에 포함하지 않는다.

## 수집과 추출 범위

| 항목 | 저장 자료에서 확인한 수 |
|---|---:|
| 수집 목록의 과목·분반 레코드 | 26 |
| 고유 학수번호 | 25 |
| 현재 목록이 참조하는 비어 있지 않은 HTML | 26 |
| 중복 제거 후 문서 | 25 |
| 비어 있지 않은 추출 문서 | 25 |
| HTML만으로 구성된 문서 | 8 |

HTML 폴더에는 36개 파일이 있으나 현재 목록에서 참조하지 않는 파일이 10개 있다. 폴더의 파일 수를 수집 과목 수로 보고하지 않는다. 현재 목록의 저장 파일 존재 여부를 검증한 것이며 전체 수집 대상 대비 성공률은 원래 모집단을 알 수 없어 계산하지 않았다.

| 첨부 형식 | 수집 분반 | 비어 있지 않은 첨부 파일 | 중복 제거 후 대상 | 해당 형식 추출 기록 |
|---|---:|---:|---:|---:|
| PDF | 6 | 6 | 5 | 5 |
| HWP | 10 | 10 | 10 | 10 |
| DOCX | 2 | 2 | 2 | 2 |

‘추출 기록’은 `sources` 필드에 해당 형식이 기록되어 있다는 뜻이다. PDF·HWP·DOCX의 글자나 표를 정확하게 복원했다는 의미의 추출 정확도는 아니다.

추출 텍스트는 총 122,085자, 문서당 중앙값 4,138자다. 최소 1,795자, 최대 8,835자이며 길이만으로 내용의 충실도를 판단하지 않는다.

JSONL 본문과 개별 텍스트 파일 불일치: **0개**. 저장 문자 수 및 추출 보고서 문자 수 불일치: **0개**.

## 중복 본문 제거와 분반 정보 보존

중복 판정은 동일 과목명 안에서 `difflib.SequenceMatcher` 유사도 0.90을 적용한 기존 결과다. 이 분석은 그 판정의 의미적 타당성을 자동 보증하지 않고 시간표 보존을 별도로 검사한다.

- `BDSC155`: 01분반을 대표 본문으로 유지하고 02분반의 유사 본문을 제거했다. 저장된 유사도는 0.995658다.
- 원래 시간표 3개, 대표 CSV 3개, 검색 문서 메타데이터 3개다. 분반·요일·교시·시간·강의실을 함께 비교한 보존 검사: CSV **통과**, 문서 **통과**.
- 대표 문서의 시간표에는 01, 02분반이 남아 있다. 본문 중복 제거와 분반 시간표 삭제를 같은 작업으로 처리하지 않는다.

## 실제 확인한 품질 문제

1. **HTML의 ‘평가방법 미입력’ 안내를 그대로 정답으로 쓰면 안 된다.** 이 문구가 16개 문서에 있고 그중 9개는 첨부파일 텍스트도 있다. 예를 들어 `BDSC302`의 HTML은 미입력 안내를 포함하지만 PDF에는 과제·시험 배점이 존재한다. 원문 채널 간 우선순위와 충돌 처리가 필요하다.
2. **HWP 변환 흔적이 남아 있다.** 알려진 깨진 문자열 신호가 10개 문서에서 발견됐다. 이는 특정 패턴의 존재 검사이며 OCR 오류율이 아니다. 숫자·표의 관계와 원래 체크 상태는 별도 원문 대조가 필요하다.
3. **섹션 제목 형식이 통일되어 있지 않다.** `강의개요`, `수업목표`, `주차별 강의계획` 같은 별도 제목 형식을 가진 문서가 4개다. 현재 분할기는 일부 HWP의 강의개요를 이전 평가방법 구역에 붙인다. 검색 진단 라벨은 현재 파서 구역 이름을 그대로 기록하고 검색된 본문에 실제 근거가 있는지로 판정한다.
4. **HTML 체크박스 라벨은 선택 값과 다르다.** ‘대면 대면’과 ‘비대면 비대면’이 함께 추출된 문서가 25개다. 이를 근거로 대면·비대면을 모두 운영한다고 판단하면 안 된다.
5. **한 학기·한 학부의 소규모 스냅샷이다.** 다른 학기와 학과에 대한 일반화나 실제 학생의 수강 성공률을 이 자료로 주장하지 않는다.

## 재현 방법

이 공개 저장소의 합성 예시 데이터와 원래 수집 자료를 구분한다. 아래 `SOURCE_SNAPSHOT`에는 원래 `data/processed`와 `data/raw`가 들어 있는 폴더를 지정한다. 공개 저장소에 원문 자료가 없으면 원래 스냅샷을 보유한 환경에서 실행한다.

```sh
python scripts/analyze_data.py --source SOURCE_SNAPSHOT --output evaluation
```

Python 표준 라이브러리만 사용한다. `evaluation/data-quality.json`의 입력 SHA-256을 통해 같은 스냅샷인지 확인할 수 있다. 개인정보 값, 로컬 절대 경로, API 키는 분석 출력에 기록하지 않는다.

## 공개 서버용 정제본

기존 25개 수집 자료에서 이메일·전화번호·로컬 파일 경로와 불필요한 URL 쿼리를 제거했다. 반복 확인된 HWP 깨진 문자만 지우고 누락된 문장이나 평가값을 만들어 채우지 않았다. 공식 강의계획서 링크, 학사 메타데이터, 26개 분반과 34개 시간표는 보존했다. 정제 전후의 본문 숫자도 연락처·주소를 제외하고 순서까지 대조했다.

정제본으로 기존 기능 회귀 103개를 다시 통과했고 서버 재시작 후 외부 실행 환경에서 동일한 25개 자료와 해시를 확인했다. [데이터 정제 기록](../evaluation/hosted-data-checks.json) · [공개 서버 확인](../evaluation/hosted-deployment-checks.json). 원본 분석과 서버 정제본의 해시는 서로 다르며 현재 자료의 추출 품질 한계가 모두 해결됐다는 뜻은 아니다.

## 평가 해석과 남은 검증

새 검색 진단 질문 30개는 저장 원문을 읽고 에이전트가 작성한 것이다. 정답 근거는 생성 답변에서 추출하지 않았으며 검색 결과를 보기 전에 작성했다. 사람이 작성한 블라인드 홀드아웃이나 실제 사용자 평가가 아니다. 이 세트로 구현을 튜닝하고 같은 점수를 최종 성능으로 발표하면 안 된다.

공개 전후의 후속 실험에서는 원문 표·체크박스 대조, 새 학생 질문의 별도 수집, 학기 변경 시 데이터 갱신 검증을 수행할 수 있다. 현재 보고서가 완료한 것은 저장 자료의 수량·메타데이터·일관성·시간표 보존 확인이다.
